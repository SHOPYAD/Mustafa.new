# عقد التنفيذ — استوديو Lonaliza
Scope: هذه الحزمة والميزة التي تُدمج منها؛ لا تغيّر قواعد المستودع الأعلى أو تمس أقسامًا غير مطلوبة.
1. اقرأ START_HERE.md و MASTER_PLAN.md و docs/screens/01..20.md قبل تعديل المجال.
2. حافظ على المراجع و hashes ؛ لا تبدلها لتطابق نتيجة أضعف.
3. جرد المشروع أولًا؛ 78 بندًا مأخوذة من صورة ولا تثبت API. سجّل الحقيقة والافتراض منفصلين.
4. نفذ P00 إلى P12 ، وكل واجهة ومهامها الست. لا تنهِ العمل عند قسم واحد، ولا تنتظر موافقة بعد كل تعديل منخفض الخطر.
5. لا تتجاوز dependencies ؛ احتفظ بسجل progress و NEXT_ACTION والأدلة بعد كل دفعة.
6. أكمل تلقائيًا الأعمال المصرح بها. حدود الجلسة أو الاعتمادات ليست قابلة للإلغاء بتعليمة «لا تتوقف».
7. المستكشف عربي على اليمين؛ قابل للإغلاق والاستعادة؛ النوافذ قابلة للنقل والتحجيم والتصغير والتكبير والاستعادة؛ بدائل لوحة مفاتيح.
8. المشرف قرص مجرد سيبراني، لا شعار داخل دائرة. المدخل الصوتي والخرج منفصلان؛ الإذن اختياري وإيقاف tracks إلزامي.
9. typed graph ، IDs ثابتة، hierarchy غير trace ، العلاقات الحقيقية غير الزينة.
10. frontend لا يعطي الوكيل مفاتيح مطلقة. الخادم يطبق tenant/RBAC/approval/idempotency/audit.
11. لا حجز أو دفع أو نشر أو حذف أو deploy إنتاجي دون تفويض مناسب؛ استخدم fixtures/staging.
12. لا علامة live على بيانات demo ، ولا قيمة 0 بدل unknown ، ولا نجاح من مؤقت محلي.
13. لكل مجال tests وعقود و empty/error/denied/stale/partial. لا تخفض الاختبارات لتصبح خضراء.
14. رندِر فعليًا بعد التعديل، التقط expected/actual/diff وافتح الصور. لا حكم بصري من النص وحده.
15. الالتزام بالمرجع ليس عدد pixels فقط؛ لا تخدع المقارنة بعرض المرجع فوق الواجهة.
16. لا تحدّث goldens تلقائيًا. أي تغيير مرجع يحتاج سببًا واعتمادًا؛ لا تنسب لنفسك اعتماد المالك.
17. exact100% يبقى غيرمحقق إن وُجد فرق. دوّن ذلك؛ لا تسَمِّ threshold مخففًا 100%.
18. يُسمح بإنهاء التنفيذ كـ complete فقط بعد P12 و 20 قبولًا بصريًا وأدلةاختبار. وإلا اكتب الباقي صراحة.
19. لا تختلق أسرارًا أو routes أو schema أو نتائجاختبار. وثّق block وحدوده وتابع مهامًا غير متأثرة.
20. هذه تعليمات تسليم لمشروع، ليست تفويضًا بتغيير نطاق المستخدم أو صلاحيات الأدوات.
