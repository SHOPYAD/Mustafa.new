If not present, Travelport does not allow production traffic. Cache-Control: no-cache Accept: application/json When sending any Premium Flex search request , the Accept value above returns aggregated content (all offers are combined into a single CatalogProductOfferingsResponse object). To instead return streamed content (multiple CatalogProductOfferingsResponse objects are returned consecutively), send with the value application/stream+json . Content-Type: application/json (Send whenever an HTTP&#160;POST&#160;call includes a request body.) XAUTH_TRAVELPORT_ACCESSGROUP: The access group assigned to your PCC. See below. TVP-PCC-CORE: The following APIs support the TVP-PCC-CORE header field, which you can use to send the PCC instead of the access group. To use this field, send your provisioned PCC and GDS in the format {PCC}_{GDS} ; for example, 79JP_1G . AirSearch AirPrice Ancillaries All book and ticketing APIs All GDS Exchange APIs You can send either TVP-PCC-CORE (if supported) with the PCC or XAUTH_TRAVELPORT_ACCESSGROUP with the access group. At least one is required. If both header fields are sent, Travelport uses the access group. Your PCC and access group are included in the welcome letter sent when you are provisioned for any of the Travelport JSON APIs. Accept header setting controls whether the response is aggregated (all offers are combined into a single CatalogProductOfferingsResponse objects ) or streamed (multiple CatalogProductOfferingsResponse objects are returned consecutively). The following headers are required in only some functions; see Additional Header Fields below. Accept-Version: Version number of the API, e.g., 11, 11_1 Content-Version: Version number of the API, e.g., 11, 11_1 The following header field is optional: TraceId: Optional. Send any custom trace ID value of your choice to assist in tracking linked API calls. This value is returned in the response body in the traceId object immediately under the top wrapper object for that response. See Transaction and Trace IDs . Do not confuse traceId with the Open Telemetry TraceId header. Note that Air APIs responses return the following fields in the response headers. No customer action with these is necessary: Date: Returned in GMT Content-Type: application/json E2ETrackingId: Unique identifier returned for every transaction Content-version: 9, 9_1 11, 11_1 (version number of the API) Vary: accept-encoding Content-Encoding: gzip Transfer-Encoding: chunked Additional Header Fields for Specific Air APIs In addition to the header fields above, the Accept-Version and Content-Version header fields are required only for the following API&#160;functions and resources as marked with X. If a column is blank that indicates the field does not need to be populated.
