# الاستوديو العصبي — سجل التنفيذ المرتبط بالمصدر
تاريخ البدء: 2026-09-28. الأصل: `71e8c70340ce88ab4948899979a916d1ae586b26`.
فرع العمل: `codex/neural-studio-20260928`. لا تعديل لـ main، ولا نشر أو أوامر إنتاجية.

## الحكم الهندسي
المكتبات ليست العائق الرئيسي. المستودع يعلن Three.js / React Three Fiber / Postprocessing / D3 / Zustand / LangGraph / Qdrant / BullMQ بالفعل. وجود الحزمة في package.json لا يثبت صحة استعمالها أو جاهزية الخدمة.
الخلل الذي أثبتته قراءة الملفات هو الفصل بين الشكل والدلالة: أزرار تعد بأفعال لا تنفذها الأدوات، نجاح افتراضي عند فشل الشبكة، قياسات وعلاقات مكتوبة مسبقاً، وبناء يسمح بأخطاء TypeScript. إضافة توهج إلى هذه البنية لا تنتج غرفة عمليات موثوقة.

## الأدلة التي حددت ترتيب العمل
- `useSecondBrainStore.ts`: كان يستعمل `resLive?.ok ?? true` ومعاينة تعتمد مؤقتاً وتدّعي فحص Zod لم يحدث. أزيل ذلك في الدفعة الأولى.
- `second-brain-directive/route.ts`: كان يقبل toolKey والهوية من العميل، يتجاهل فشل الأداة، ثم يعيد ok:true. استُبدل بحاجز مصادقة وتعريف إجراء وصلاحية أداة على الخادم.
- `second-brain-data/route.ts`: ينشئ عميل Qdrant لكنه كان يعيد سبعة سجلات مختلقة وعدداً ثابتاً 259. أصبح يقرأ metadata فعلية للمجموعات مع partial/unavailable ولا يعرض محتوى محادثات العملاء.
- `agent-stream/route.ts`: لم يكن يستدعي assertAdminApi؛ أُضيف الفحص. العزل الدقيق لكل tenant/session وإعادة بث الأحداث ما زالا ضمن P03/P08.
- `sovereignDomainGraph.ts`: أرقام الإيراد والصحة وRPS وزمن الاستجابة ثابتة. «تطهير كاش الطيران» يستخدم flights_runtime الذي يقرأ الإعدادات فقط. لا تعتمد هذه البيانات كمصدر حي.
- `agent-war-room/route.ts`: المسار الصوتي يحقن قياسات ثابتة ويطلب تأكيد التنفيذ قبل نتيجته، ويطلق مداولة في الخلفية دون انتظار مع consensusScore ثابت. هذا **لم يُصلح بعد** في الدفعة الأولى؛ محادثة الاستوديو الجديد غير مفعلة حتى يُستبدل المسار بعمليات موثقة.
- `langgraph-engine.ts`: درجات ROI/confidence وبعض الهوامش ثابتة، والبث يجري بعد اكتمال الرسم في قسم من التنفيذ. يحتوي كذلك استدعاءات تخزين لا تطابق الأنواع المعلنة في agent-collab-store. يحتاج اختبارات من طرف إلى طرف قبل إطلاق الحكم الذاتي.
- `next.config.ts`: ignoreBuildErrors:true. لذلك نجاح next build وحده ليس دليلاً على سلامة الأنواع. نضيف فحصاً صارماً للملفات الجديدة منفصلاً قبل معالجة الديون القديمة.
- backend وadmin-panel كلاهما يعلنان Next.js. لا نعيد بناء Fastify/PostgreSQL لمجرد ظهورهما في mockup. توزيع الخدمات الفعلي وإعدادات النشر يجب إثباتهما قبل دمج أو نشر أي تعديل.

## حدود التحقيق
الفهرس الإداري غير مبتور: **81 ملف page.tsx و193 ملف route.ts إداري**.

لم تُقرأ كل ملفات المنصة أو بيانات الإنتاج. هذه أرقام محددة لشجرة admin-panel/src، وليست تعداداً لكل المنصة.
`source-inventory.json` يحتفظ بالمسارات وبصمات ملفات الصفحات. وجود الملف ليس فحصاً لاتصال مزود أو إثباتاً لتطبيق صلاحيات كل endpoint.
لا توجد علاقة calls آلية في الفهرس حتى يثبتها استخراج static imports/fetch أو trace موثوق؛ التجميع الحالي contains فقط.

يلزم فصل قبول الوظائف وقبول التصميم وقبول التكامل. لا نسبة إجمالية تخفي فشل أي منها.
إعادة بناء رسم مولد من صورة مسطحة لا تضمن تلقائياً المساواة البكسلية؛ لا نغيّر الهدف ولا ندّعي تحقيقه دون دليل.

## العمارة المستهدفة
المستخدم/الصوت → intent مهيكل → capability موثقة → سياسة المستخدم والوكيل والمستأجر → preview → اعتماد عند اللزوم → command ledger + queue → محول خدمة موجودة → حدث موثق → graph + inspector.
الفصل إلزامي بين فهرس مصدر الكود، الرسم التنظيمي، ارتباطات الخدمات المثبتة، traces الإجراءات، والطبقة الفنية الزخرفية.
تُعاد استخدام الخدمات الحالية عبر adapters. لا يستدعي المتصفح endpoint يكتبه النموذج، ولا يختار هوية الوكيل، ولا تُمنح صلاحية SQL/نظام ملفات مفتوحة للمشرف.

### عقد الإجراء
commandId / idempotencyKey / tenantId / actorId / agentId / capabilityId / schemaVersion / expectedVersion / approvalRef / traceId.
الحالات: received → validated → awaiting_approval أو queued → running → succeeded/failed/needs_reconciliation/cancelled.
مهلة HTTP ليست دليلاً على فشل عملية حجز عند المزود؛ حالة غير مؤكدة تحتاج reconciliation قبل أي retry.
تُمنع الكتابة إذا غاب محول معتمد. العمليات المالية والنشر والحجوزات الفعلية تحتاج اختبار sandbox واعتماد سياسة، ولا يجري تشغيلها أثناء اختبار CI.
الموافقة تُخزن خادمياً على hash المعطيات + المستأجر + الفعل + مدة صلاحية؛ confirmed:true في الطلب لا يُعد تفويضاً.
سجل التكرار يجب أن يكون دائماً ومشتركاً بين workers، لا Map في ذاكرة العملية. لا تسوية مالية تلقائية بإجراء عكسي غير مدعوم من المزود.

### عقد البث
eventId / streamId / sequence / occurredAt / schemaVersion / entityId / traceId / sanitizedPayload.
snapshot + watermark، ثم أحداث مرتبة لكل stream. تكرار الحدث يُحذف؛ فجوة sequence تفرض resync.
مهمة HTTP المستمرة أو EventEmitter المحلي لا تكفي لتعدد العمليات؛ نستعمل البنية الموجودة Redis/BullMQ بعد إثبات تشغيلها، مع تخزين دائم للحالات.
الرسوم تبين تقدم الأداة وأحداثها، لا تدّعي كشف التفكير الداخلي للنموذج.

اختبارات desktop/mobile وإعادة التحميل والفراغ و503؛ تصوير التنفيذ الفعلي من المكونات الإنتاجية.
محاكاة الميكروفون ممنوعة؛ الموجة الحالية قياس حقيقي فقط، وليست محادثة عاملة أو حلاً مكتملاً لمرجع17.

### P03 — الرسم والبيانات

## كيف تُقرأ أدلة الاختبار
اختبارات الدفعة الأولى شغّلت route handlers الحقيقية مع mocks لحدود المصادقة والخدمات، وليست طلبات حية للمزودين.
الحزمة quality/neural-studio معزولة حتى لا تُخفي مشاكل المشروع القديم أو تتطلب مفاتيح إنتاج.
اختبار UI يحمّل نفس مكونات src وليس HTML بديل. مصدر البيانات fixture معلّم في ملف الاختبار فقط؛ لا يوجد fallback fixture داخل المنتج.
نجاح هذه الاختبارات لا يساوي نجاح build المنصة كلها، ولا يثبت مطابقة الـ20، ولا جاهزية التصرف المالي.

## الأعمال المتبقية لا تُخفى
- الاستوديو الجديد أساس تفاعلي وفهرس مصدر؛ ليس تنفيذ كل واجهة مجال نهائية.
- لا تفعيل مشرف صوتي تنفيذي جديد حتى يمر مسار الأمر والسياسة والتخزين الدائم بالاختبارات.
- العلاقات الفعلية بين مكونات الخلفية لم تُستخرج كاملة بعد.
- تقييم المراجع العشرين ما زال pending؛ فشل مقارنة مرجع01 حاجز تسليم حقيقي.
- لا نشر، ولا دمج، ولا فواتير/حجوزات/إعلانات حية نُفذت في هذه المهمة.
